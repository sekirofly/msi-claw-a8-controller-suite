# MSI Claw A8 Controller Suite：融合设计草案

## 最新确认：两状态管理（覆盖下文旧的首次手动启用与暂停流程）

首次安装默认启用，第一次写入前保存原始输出及配置，后续不覆盖这份快照。启用期间重启、唤醒或会话恢复后自动重新应用套件状态；正常输出不反复重建。点击“恢复原配置并停用”后持久停用，重启也不接管，直到点击“启用管理”。界面只展示启用/停用两种选择，应用或恢复失败单独显示具体错误与重试，不宣称成功。更新保留选择；干净重装重置设置。外接设备隔离、写前身份核验和失败保护不变。

状态：设计评审中；2026-11-07。独立复制模型已获用户确认；已获准开始分阶段实现。源码冲突与待验证项见[合并前审查](integration-review.zh-CN.md)。

## 1. 目标与范围

将 DeckyPlumber 的输入映射、按游戏配置，与现有插件的背键硬件模式、左右震动强度整合为一个 Decky 插件。只做简体中文和英文。

产品只管理 MSI Claw A8 内置手柄，底层固定使用 Xbox Elite，不提供虚拟手柄类型选择。所有按键界面按 A8 实体布局显示：M1/M2、A/B/X/Y、方向键、摇杆、肩键、扳机和实际菜单键；不展示不存在的额外背键或其他机型控件。Steam 可能仍识别为 Xbox Elite 并显示四背键，不修改 Steam 布局。

蓝牙及 USB 外接手柄不在管理范围。必须依据 A8 硬件身份与来源设备关联，唯一确认对应的 InputPlumber 设备；不能用 CompositeDevice0 或“第一个手柄”代替识别。无法确认时停止写入。

首次打开只读取现状。首次启用“管理 A8 内置手柄”时保存原配置，必要时将已确认的 A8 输出设为 Elite，保留其所需键盘/鼠标等辅助输出；说明可能短暂断连。已是 Elite 时不重复重建设备。停用管理时尝试恢复接管前配置；结果逐项反馈。其他软件改变输出类型时暂停映射并提示重新启用，不循环抢写。

保留映射方案的新建、编辑、复制、删除、多方案组合及内置预设；保留更新、重装、卸载与诊断。首版不加入陀螺仪调参、死区校准、宏录制、RGB 或功耗管理。

## 2. 现有界面问题与改法

以下来自 DeckyPlumber `cebd2fc` 的界面代码检查，尚未做掌机可用性测试。

| 当前问题 | 融合后的处理 |
| --- | --- |
| 所有映射方案直接变成侧栏开关，方案越多侧栏越长 | 侧栏只显示当前方案摘要，列表和编辑移到完整设置页 |
| “Controller Mode”容易与背键模式混淆 | 移除虚拟类型选择，仅保留明确命名的“背键硬件模式” |
| 当前游戏标题截断到 10 个字符，编辑范围不醒目 | 显示完整游戏名（可换行）及固定的“编辑默认按键 / 编辑《游戏名》” |
| 编辑入口是“管理 → … → 编辑 → 映射弹窗” | 列表行直接打开编辑页；省略号仅放复制、删除等次要操作 |
| 映射需要先选类型、子类型、原始事件名 | 先展示 M1、M2、菜单键等常用来源，其他实际 A8 输入放“其他按键”，不暴露其他机型的输入列表 |
| “合并基础配置”直接展示文件路径 | 默认保留系统基础映射；高级设置解释作用，路径只放诊断 |
| 更新、重装与常用控制混排 | 收进“维护与关于” |

## 3. 菜单结构：高频操作在首页，低频设置下沉

页面使用“默认按键”和“游戏专用按键”，不用含糊的全局/游戏切换器改变同一组控件的作用范围。按键编辑与硬件设置分区，配置库不与当前游戏混排。

```text
侧栏首页
  MSI Claw A8 · 内置手柄连接状态
  当前游戏：《完整游戏名》（无游戏则显示“未运行游戏”）
  当前按键：默认按键 / 《游戏名》专用 / 正在应用 / 应用失败
  M1 → 当前动作；M2 → 当前动作（只读摘要）
  [编辑《游戏名》的按键] 或 [为《游戏名》单独设置]
  震动强度 · 所有游戏共用
    左滑块 / 右滑块
    [测试震动 · 0.5 秒]
  [打开设置]

完整设置页（左侧三类）
  按键配置
    默认按键 → 独立编辑页
    游戏专用按键 → 游戏列表 → 独立编辑页
  手柄设置 · 所有游戏共用
    背键硬件模式、震动
  维护与关于
    插件管理（启用 / 恢复原配置并停用）
    更新、重装、卸载、诊断
```

模板库作为独立页面及其存储已移除（2026-11-09 决定）。复制来源只剩“默认按键”和已有的游戏专用配置；旧配置里的 `templates` 键在读取时丢弃，下次保存不再写回。内置预设若日后加入，作为编辑页内的只读来源，不恢复独立页面。理由与影响见第 4 节。

背键硬件模式从侧栏首页移除。其设置页保留 Macro / Combination / Disabled 三种原名和说明。只有背键不可用等关联异常时，首页出现“检查背键设置”提示和直达入口，不自动改模式。

插件管理（是否接管内置手柄）与安装维护同属低频、可破坏状态的操作，统一放在“维护与关于”，避免与背键模式、震动这类设备属性混在同一分组。

已有专用内容但停用时，首页显示“使用默认按键（本游戏专用已停用）”及“编辑本游戏专用按键”，编辑页提供重新启用；不能再次创建第二份。

没有运行游戏时，首页按钮为“编辑默认按键”，不展示游戏开关或空游戏页。游戏运行且尚无专用设置时，首页只提供“为《游戏名》单独设置”，不把“编辑默认按键”伪装成“修改当前游戏”。默认按键始终可以从设置页明确进入。

## 4. 编辑范围与生效规则

### 默认与专用：完整副本，不做逐项继承

- **默认按键：**用于没有启用专用配置的游戏，以及退出游戏后的桌面/主界面。
- **游戏专用按键：**每个游戏最多一份，以稳定的游戏 ID 标识，名称仅用于显示。创建时可从默认按键或另一游戏的已保存配置复制，成为独立完整副本。之后修改任意来源都不会改变副本；不做共享引用或部分按键继承。
- **复制示例：**《黑暗之魂 3》→“从已有配置复制”→《艾尔登法环》→预览→“保存并为《黑暗之魂 3》启用”。之后两份互不影响，不提供直接关联另一游戏配置的“使用此方案”。目标已有专用配置时复制只替换编辑草稿，确认保存后覆盖，不创建第二份配置。取消不改变已保存数据。复制不包括来源游戏 ID、启用状态、震动、硬件模式或设备信息。
- 游戏编辑页固定显示“正在编辑：《游戏名》”，范围不可在编辑途中切换。游戏运行/退出也不会让编辑器自动换到另一份配置。
- 编辑默认按键时固定显示“影响所有使用默认按键的游戏；不影响已有专用配置”。震动和背键硬件模式不属于这两类按键配置，不出现在游戏编辑页。
- 专用配置页提供“使用本游戏专用按键”。取消后当前游戏使用默认按键，但保留专用内容供再次启用；删除配置另行确认。“重新复制默认按键”说明会覆盖专用内容并需确认。
- 首版不再另加一个“启用按游戏配置”总开关。第一次保存并启用某游戏专用配置，就是用户允许该游戏自动使用它；没有启用的游戏始终用默认按键。

### 状态与保存：始终说明改谁、什么时候生效

编辑页顶部固定显示范围及状态，例如：

```text
正在编辑：《艾尔登法环》的按键
仅影响本游戏 · 当前未运行，保存后下次启动生效
M1 → A
M2 → B
[保存到《艾尔登法环》]   [取消]
```

- 当前游戏的已启用配置：保存成功后应用并验证；未运行游戏：只保存，不改当前手柄。首次创建使用“保存并为《游戏名》启用”，取消创建不留下已启用空配置。
- 默认配置：保存后，如果当前正在用默认按键就立即应用；当前使用游戏专用按键时不改变当前输入。
- 顶部“当前按键”来自已确认生效的状态，不能拿正在编辑或等待应用的配置冒充成功。保存成功但应用失败时显示“已保存，未生效”，保留实际状态和重试入口。
- 编辑游戏 A 时即使游戏 B 启动，仍只保存到 A；执行前重新判断当前游戏，不能把 A 的配置应用到 B。返回有未保存修改时提示保存或放弃，焦点回到原入口。
- 震动滑块约 200ms 合并保存，背键硬件模式在设置页点选即生效，均不需要应用按钮。两处震动控件共用同一实际状态，并始终标注“所有游戏共用”。

### 复制来源与映射编辑（原“模板库与映射编辑”）

独立副本模型下，复制来源只有两类：默认按键，或另一个游戏的已保存配置。原先的“模板库”页面已移除——它只提供命名的草稿，不会跨配置同步，却额外引入了“模板 / 默认 / 游戏”三种概念的区分成本。其存储字段一并删除，旧文件中的残留键在读取时丢弃。

若日后加入内置预设（例如菜单键互换），预设是插件提供、只读、随插件版本更新，应作为按键编辑页内的一个复制来源，不恢复独立页面，也不与用户配置混存。

保留组合能力，但收在按键编辑页的“高级：组合方案”；方案按顺序复制合并，同一输入后者覆盖前者，预览冲突与最终动作，不保留隐式共享引用。保留未被覆盖的系统基础映射。“完整副本”指插件可编辑的按键规则，不是冻结或复制整份系统设备配置；基础配置单独保存、带版本校验，不随游戏复制。导出给 InputPlumber 的映射不得携带改变输出类型的字段，恢复原配置走独立路径。

普通编辑先呈现 M1/M2，再列 A8 实际其他按键，使用“输入 M1 → 输出 A / 键盘键 / 鼠标动作”表达。不存在的额外 Elite 背键不展示；检测不确定的实际输入标为“待验证”。硬件模式导致独立背键事件不可用时解释原因，提供设置入口，不偷偷切模式。多目标映射不称为延时连招。

底层固定 Elite，游戏进退只改变映射，不重建输出。退出游戏恢复默认。首次安装或未接管时只读；已启用管理的后台在重启/唤醒后，重新确认身份、接口和恢复快照，再恢复当前应使用的配置。仅打开面板不触发额外应用。外部软件改变设备状态时暂停并提示，不抢写。Steam Input 若另设映射仍可能进一步转换输出，插件不覆盖其配置。

## 5. 代码如何合并

合成一个插件、一个配置入口、一个负责实际写入的后台；不把两份插件各自的启动和自动同步逻辑同时塞进去。

```text
界面：状态展示、快速控制、配置编辑
                    ↓
配置选择：已启用的当前游戏完整配置，否则使用默认按键
                    ↓
统一执行层：校验 → 排队 → 保存快照 → 写入 → 验证/恢复
             ↙                         ↘
A8 硬件接口                       InputPlumber 接口
背键模式、左右震动                 固定 Elite 输出、按键映射
```

复用现有硬件读写、合并保存、安装校验逻辑；借鉴/复用 DeckyPlumber 的映射编辑与配置能力，重新组织界面和执行流程。设备动态查找，不写死 CompositeDevice0；缺少 InputPlumber 时，已可用的硬件控制仍能使用。

保存的配置、待应用的设置和设备实际状态分开记录。所有变更进入同一串行队列；游戏切换、滑块和维护操作不能并行改设备。仅在启用管理或经用户发起的恢复时确保 Elite 输出，重新发现设备就绪后再应用映射；普通映射变更不触发类型设置。变化期间合并为最新期望配置，失败后停止后续写入并刷新状态。

跨硬件与 InputPlumber 的修改不是原子事务，不能保证失败时全部自动还原。恢复结果逐项反馈；提供桌面终端恢复入口，避免手柄失效后只能靠手柄点击“恢复”。不自动重启 InputPlumber、不自动重置 EC。这里的恢复指接管前的 InputPlumber 输出及映射，不重置用户设置的硬件背键模式和震动。干净卸载/重装应先停止自动应用并恢复接管前状态，再删除文件；恢复失败不删除唯一恢复快照，并告知下一步。普通更新保留配置与快照。

仅借用可独立使用的模块；复用代码保留上游署名与许可，新项目按 GPL-3.0-only 发布。保留旧插件独立仓库；融合版上线时要求停用原两插件的控制逻辑，避免多个自动配置来源竞争，不静默卸载它们。

## 6. 首版验收

1. 首次安装/未接管时只读；打开面板不额外写入，已启用管理的后台可以按约定恢复配置。没有 InputPlumber 时仍可调已支持的硬件项。
2. 按键界面与 A8 实体布局对应，无虚拟类型选择或额外 Elite 背键；M1/M2 对应经实机确认，不修改 Steam 布局。
3. 背键和震动仍保持现有操作体验，读回失败时不显示成功。
4. 默认与游戏专用配置可创建、编辑、复制、删除；复制来源与目标明确，复制后互不联动，同一游戏无法建立第二份专用配置。
5. 首页不含背键硬件模式；编辑范围固定可见。验证从另一游戏复制后相互独立、同一游戏无法创建两份专用配置、默认修改不影响专用副本、专用停用保留内容、编辑中切换游戏不串配置，以及保存成功但应用失败的提示。游戏进退、睡眠唤醒及外接手柄不会改错设备。
6. 首次启用及停用管理验证输入、菜单键、背键、震动及恢复原配置；异常有独立于手柄的恢复方法。蓝牙/USB 外接手柄在接入、断开、设备重排时都不能成为写入目标。
7. 全程可用手柄导航，返回后焦点合理；中英文内容一致。安装后重启及可能需要 EC 恢复的已知说明继续保留。

评审通过后分阶段实现：先统一硬件控制与状态，再做固定 Elite 接管及恢复，然后映射管理，最后按游戏自动配置。

## 7. 测试震动

全局震动滑块下提供测试按钮，先完成强度保存，再对唯一确认的 A8 内置设备发送最长 0.5 秒力反馈效果。后端串行执行并限制重复请求，效果自带时限，finally 停止/释放本次效果，不调用全局停止震动。接口不支持或设备身份不明确时禁用并解释，绝不尝试其他手柄。自动测试不能证明实机马达响应，需 A8 验证当前强度是否实际影响测试效果。
