# 合并前审查：设计与父项目的差异

> 历史设计/研究参考；当前行为和安装说明以 README 为准。

## 后续决策

用户已确认采用默认启用、持久停用的两状态管理，取代本文首次手动接管及恢复后重新启用的旧流程。Alpha.16 已取消原配置快照：从本机安装的系统默认配置构建映射，停用恢复系统默认；失败显示错误并提供重试。具体规则见设计文档“最新确认”。以下为原始整合评审记录。

2026-11-07；仅源码审查，未在 A8 做新增功能测试。当前需求以[设计文档](design.zh-CN.md)为准。结论：可以进入分阶段实现，但不是直接拼接两个插件；以下项目必须改写或验证。

审查基线：[小插件 v1.0.1](https://github.com/sekirofly/msi-claw-a8-back-buttons-rumble/tree/v1.0.1)、[DeckyPlumber cebd2fc](https://github.com/aarron-lee/DeckyPlumber/tree/cebd2fcab2f6bc17968d1d4c4bf8cb9fa992b3a5)、[InputPlumber 6aca920](https://github.com/ShadowBlip/InputPlumber/tree/6aca9202fb8dfd6f31241c3f98b72df4a775c1a1)。上游当前能力不代表掌机已安装版本具备相同接口。

## 已明确的产品规则

- 只管理 A8 内置手柄；底层固定 Elite；不展示不存在的按键。
- 默认一份、每游戏最多一份专用按键配置。复制来源可以是默认、其他游戏或模板，复制后互不关联；游戏 ID 是标识，不能用游戏名称作唯一键。
- 停用专用配置保留内容，删除另行确认。目标已有配置时复制覆盖草稿，保存才替换，取消无副作用。
- 复制只包括按键规则，不复制来源游戏身份、启用状态、硬件模式、震动或设备快照。硬件两项仍为全局，模式只放二级设置。
- 模板可重复使用，但不自动同步到游戏；不显示“关联了多少游戏”，因为没有共享引用。

## 明确的代码冲突及处理原则

| 项目 | 源码证据 | 融合版处理 |
| --- | --- | --- |
| 游戏配置模型 | DeckyPlumber `controllerSlice.tsx` 的 `activeProfiles` 存放方案 ID；`mapping_profiles.py` 每次从共享方案取规则 | 新建独立数据模型，深复制按键内容；保存/删除采用明确替换，不直接沿用共享引用和递归 merge |
| 内置设备隔离 | DeckyPlumber `controller_utils.py`、`mapping_profiles.py` 写死 `CompositeDevice0`；小插件 `main.py:_find_device` 只按三个 sysfs 属性筛选唯一候选 | 两边都需加强：主机 DMI + 内置设备来源/物理拓扑关联，唯一确认后写入；同型号外接或重枚举也不能靠“第一个”判断 |
| 初始化与并发 | DeckyPlumber 前端初始化及游戏变化会同步，另有防抖保存；小插件串行/合并机制主要在前端组件内 | 后台统一串行执行，区分保存、应用与实际状态；引入配置修订和设备代次检查，过时任务不得覆盖新游戏或新设备 |
| 固定 Elite 与隐式切换 | DeckyPlumber 的 Default 路径可能重启 InputPlumber；InputPlumber `composite_device/mod.rs` 加载 profile 时会处理 `target_devices` | 删除类型切换产品逻辑；游戏配置不得携带目标类型。保留基础映射时单独处理设备级字段，不能整份原 YAML 直接反复加载 |
| 快照与验证 | DeckyPlumber `capture_base_profile` 主要保存路径/名称，可能回退系统默认；部分应用异常只进日志 | 优先探测 `GetProfileYaml` 等读取接口，持久化实际内容与目标集合；快照不可确认时不启用映射接管。成功调用与实际读回分别记录，不能只凭名称宣称验证成功 |
| 组合冲突 | DeckyPlumber `build_combined_yaml` 把自定义映射追加合并，没有实现我们承诺的同源“后者覆盖前者” | 规范化输入键，显式消除同源冲突并展示预览；复制结果存实体规则，不存模板 ID 链接 |
| 睡眠恢复 | DeckyPlumber `main.py:on_suspend/on_resume` 仅记录日志 | 新增设备重新发现和受控恢复。承诺是恢复配置，不是修复底层失联或 EC 故障 |
| 卸载与重装 | 小插件 `installer.py` 删除本插件文件/配置；`_unload/_uninstall` 不恢复硬件或其他服务状态 | 原小插件行为保留；融合版须新增 InputPlumber 状态释放流程。恢复快照独立保存，恢复失败不随清理删除。硬件震动/背键模式不重置 |

另有一个设计措辞冲突已修正：“打开面板只读”不等于“已启用管理后后台永远不写”。首次安装未接管时只读，已授权的游戏切换/启动恢复由后台执行，打开面板本身不额外触发写入。

## 开始实现前需划清的边界

1. **M1/M2 模式兼容尚未验证。** 三种硬件模式可切换已获用户验证，但不等于各模式均产生独立背键事件。需逐模式验证按下/松开、左右对应及普通键名称；不可据模式名称猜行为。系统能力列表也不能替代实际按键测试。
2. **设备能力与接口版本尚未知。** 第一阶段提供只读诊断，核对本机 InputPlumber 的版本、来源设备路径、输出类型、当前 profile 读取接口及权限。有缺项就关闭对应接管功能，保留已支持的硬件项。
3. **Steam Input 可以继续转换输出。** 插件按键映射不是游戏最终动作的保证；我们不修改 Steam 配置。映射键盘/鼠标也可能受游戏混合输入支持影响，不能承诺所有游戏同样表现。
4. **后台只能处理可靠的当前游戏标识。** 初版按 Steam 报告的稳定 App ID 工作，名称仅展示；非 Steam 游戏需经 Steam 启动且可取得有效 ID。多游戏同时运行或状态不明时保留已知配置、提示未确认，不凭短暂空值误切默认。
5. **防止丢失操作入口。** Guide/QAM 等菜单键首版显示但保护其基础功能；高级改写推迟到恢复路径验证之后。配置切换需测试按键按住时的释放/卡键风险。终端恢复不依赖手柄导航。
6. **先停用原两个插件的控制逻辑。** 不能只关闭它们的 UI：DeckyPlumber 后台可能继续应用配置。新插件不静默卸载旧插件，也不宣称能可靠发现所有外部写入者；发现状态冲突时暂停提示。

## 建议实施顺序与放行条件

先做配置模型和只读探测，再移植硬件控制，随后实现固定 Elite 接管/快照恢复，最后接入映射与按游戏应用。可以先写模拟测试，无需把未知硬件行为当作已支持。

发布可安装测试版前必须验证：外接手柄隔离、游戏副本不联动、保存/应用失败区分、进退游戏和唤醒恢复、按住按键时切换、卸载/重装恢复快照。已知安装后重启及可能需要 EC 恢复的说明继续保留。

无需再次选择共享还是复制；复制规则已确定。待真机验证项是工程验证，不应通过额外界面选项转嫁给用户。首版保护菜单键和不支持模糊游戏识别属于本次提出的范围建议，仍待整体设计评审。
